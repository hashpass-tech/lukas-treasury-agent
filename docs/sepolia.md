# Celo Sepolia integration

Chain **11142220**. `TESTCOP` is a synthetic test asset, never official Ripio wFIAT. Public local test identities must never be used on the actual network. Real gas, operator-provisioned signing services and separate role wallets are required. The full deploy/fund/schedule/execute/reconcile path passed against a local HTTPS emulator with this chain ID. **No actual Celo Sepolia receipt is claimed.**

Use a separate persistent directory/database/manifest from LOCAL or mainnet. Replace or unset the LOCAL RPC_URL when selecting the remote RPC. Export the values in `.env.example` (scripts do not automatically load it): `MODE=CELO_SEPOLIA`, `CHAIN_ID=11142220`, trusted HTTPS `CELO_SEPOLIA_RPC_URL`, `SIGNER_URL`, separate role signer endpoints/credentials, public `MERCHANT_WALLET_ADDRESS`, `DEPLOYER_WALLET_ADDRESS`, `PUBLISHER_WALLET_ADDRESS`, `RECIPIENT_ADDRESS`, the permanent `AGENT_WALLET_ADDRESS`, protected `JOURNAL_KEY_FILE`, positive reviewed gas cap, and `CONFIRMATIONS=5`. Set `PUBLIC_ORIGIN` to your HTTPS dashboard origin. Keep `MAINNET_WRITES=false` and use `ORACLE_MODE=fixture` only for this test tier.

Run `pnpm config:validate`, then `pnpm deploy:sepolia` to prepare a plan. After approving the testnet signer actions and funding CELO gas, run `pnpm deploy:sepolia --broadcast`. The deployer creates TESTCOP, the fixture oracle and vault. The separate owner allowlists the token and recipient, and the deployer deposits test assets. Every operation journals encrypted signed bytes before sending and waits for a canonical successful receipt. Re-running reconciles the same operation hashes; it does not redeploy or duplicate funding. A new price fixture publication can occur and retains its original source time.

`pnpm demo:sepolia` prepares a fixed, bounded 100-LUKAS demo intent for owner authorization through the configured signer and schedules it 15 seconds later. The supplied owner signer requires approval of the exact EIP-712 hash; a third-party signer must enforce equivalent owner consent. Use `pnpm demo:sepolia --broadcast` only after approving that exact intent. Alternatively run `pnpm dev:api`, `pnpm dev:worker`, and the Next dashboard behind HTTPS; the merchant signs through its browser wallet. The worker evaluates live policy, journals before broadcast, tags bytes before signing, waits for configured confirmations and verifies the actual vault event/amount/hash. Idempotent demo IDs prevent duplicate settlement.

If a signer/RPC timeout occurs, preserve the database and recovery key, then re-run the same command. Do not manufacture a new payment ID. Pending transactions block new executor work. Fee replacements retain nonce/business terms and a gas cap. Deep reorgs invalidate receipts and converge through chain evidence. Export scrubbed receipts with `pnpm evidence:export`; verify the tag with `pnpm attribution:verify <hash>`. Inspect the **actual public Sepolia explorer receipt** before recording real testnet evidence. Testnet activity receives no mainnet hackathon credit.
