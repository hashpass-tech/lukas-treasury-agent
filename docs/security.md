# Security and operational boundaries

Financial authority belongs to the merchant's wallet. The agent holds gas and only executes exact owner-signed intents. EIP-712 binds chain/vault, recipient/token, amount, ceiling, time window, methodology, salt and policy epoch; SignatureChecker supports EOA and ERC-1271 ownership. The contract independently enforces current allowlists, executor, freshness, per-payment/UTC daily caps, cancellation, pause and replay. SafeERC20, reentrancy protection and exact sender/recipient balance changes reject nonstandard transfer behavior and roll back counters.

Remote signing is replaceable and HTTPS-only. The supplied isolated service reads a protected key file, authenticates a role-specific credential, binds one key/role/chain, requires attribution and a reviewed gas cap, simulates exact bytes and signs without broadcasting. Executor scope is zero-value `executePayment` to its configured vault; publisher scope is its configured oracle. Owner/deployer transactions and owner typed intents require unexpired exact approval records. Private nonce/business bindings and encrypted signed-response storage prevent changing a business call during fee replacement. The client separately verifies every returned signed transaction field and recovered signer. See [signer setup](signer.md); this MVP service is not an HSM.

The worker durably stores the exact prepared request before requesting a signature and encrypted authenticated bytes before sending. Crash recovery uses the same request/nonce/hash; unknown RPC outcomes freeze independent work until reconciled. Retries back off and stop for terminal or exhausted reasons; fee replacements preserve business terms within the gas cap. SQLite leases coordinate one host, not multiple machines. Never share SQLite across hosts or run another process spending from the executor outside its nonce journal.

Authentication challenges bind origin/URI, chain, wallet, nonce, issue time and expiry, are consumed transactionally once, and use chain-backed signature verification for deployed contract wallets. Remote dashboard/metrics/receipt reads require current treasury ownership. Cookies are HttpOnly/SameSite Strict and Secure remotely; mutations require allowed Origin and JSON, bounded bodies and validated input. A single-merchant request limit applies. Put the API behind an HTTPS reverse proxy with appropriate edge limits; this baseline is one configured treasury per runtime, not a public multi-tenant hosting platform.

Only LOCAL can use the public development mnemonic or synthetic fixtures. FixtureOracle and TESTCOP constructors reject chain 42220. Mainnet requires matching issued tag and permanent wallet, actual token/source code evidence, canonical identity, reviewed economic policy and explicit unexpired authorization. Disabling agent writes does not remove the owner's direct onchain emergency controls. Native/mirror price provenance must be independently accepted; code hashes do not establish issuer rights, liquidity or redemption.

Secrets, merchant signatures and raw transactions remain outside source control/browser bundles/public exports/logs. Recovery keys need secure backups; loss makes decryption impossible. Errors emit fixed codes or classes, avoiding credential-bearing RPC payloads. Audit hash chains become useful tamper evidence only with separately retained trustworthy checkpoints. Local demo artifacts contain public test identities and explicitly labeled simulation data.

Foundry and actual EVM tests cover replay, caps, stale input, malformed/wrong authorizations, precision, sender-fee/reentrant tokens, rollback, ERC-1271, restart, delayed mining, replacement and reorg. They are not an audit or proof against all rebasing/upgradeable-token behavior. Token behavior/proxy upgrades, economic exposure, role/hosting configuration, external review and operational drills remain required before real funds. No independent security review or mainnet payment is claimed.
