## Prepare a concrete plan

Supply `MAINNET_PLAN_CONFIG`: chainId 42220; separate owner/deployer/agentWallet/publisher/recipient; reviewed integer perTxCap/dailyCap/maximumGasCostNativeAtomic; maximumOracleAgeSeconds; verified tokenMetadata; reviewReference; and oracle configuration. Native mode requires source/tokenPriceFeed addresses and code hashes. Mirror mode requires sourceChainId/sourceContract and acceptedTrustReference. Use `packages/core/token-registry.ts` for the exact metadata schema. No official address or economic cap is provided as a default.

Configure trusted `CELO_MAINNET_RPC_URL`, canonical registry code/implementation hashes and the actually registered `ERC8004_AGENT_ID`. `pnpm deploy:mainnet` verifies chain/token/identity/source evidence and writes `.local/mainnet-plan.json` containing exact bytecode/ABI/configuration and `planHash`. Review this concrete artifact before authorizing a broadcast. It does not move funds by default.

For a bounded pilot, `MAINNET_AUTHORIZATION_FILE` binds chainId, attributionCode, agentWallet, operator, reviewReference, identityVerified, oracleVerified, tokensVerified, exposureCapsReviewed, expiresAt and planHash. Those statements are explicit operator decisions, not claims automatically approved by tests. `SECURITY_REVIEW_FILE` records approved, reviewer, reviewReference, sourceCommit, planHash and expiresAt for `pilot:check`; obtain it from the actual independent review. Provision separate role signers/approval files and a positive reviewed gas cap. Set mode/chain/oracle and `MAINNET_WRITES=true` only for the authorized window. `--broadcast` rechecks role addresses, mode, policy, hashes and authorization, journals before each deployment/configuration transaction, and waits for canonical finality. Vault funding is a separate owner-reviewed action.

Keep independent LOCAL/Sepolia/mainnet manifests and databases. Validate fresh sources and publish accepted oracle rounds with the operator-approved publisher, then start the authenticated API and worker behind trusted HTTPS. Register metadata/identity from the permanent event wallet using the reviewed unsigned identity transaction; the executor signer cannot become a generic identity/deployer key. Export/verify actual receipts and confirm credited event activity separately. Do not relax gates to meet a calendar.
